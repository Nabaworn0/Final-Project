# การจัดรายวิชาและห้องเรียน — ขั้นที่ 1

## ขอบเขตที่ใช้งานได้

- สร้างรายวิชา ระบุรหัส ชื่อ ปีการศึกษา พ.ศ. และภาคเรียน
- เพิ่มและแก้ไขรายชื่อนักศึกษาและอาจารย์ในรายวิชา
- ตารางนักศึกษามีเฉพาะ `ลำดับที่`, `รหัสนักศึกษา`, `ชื่อ`, `สกุล` และแก้ไขข้อมูลจากเซลล์ได้โดยตรง
- นำเข้ารายชื่อนักศึกษาจากไฟล์ `.xlsx` โดยตรวจตัวอย่างก่อนยืนยัน
- อ่านชีตรายชื่อหลายชีตจากไฟล์เดียวและสร้างแท็บห้องเรียนหลักด้านล่างตามชื่อชีต
- ภายในแต่ละแท็บสลับได้ระหว่าง `รายชื่อ` และ `แบ่งกลุ่ม`
- สร้างและแก้ไขห้องก่อนสอบกลางภาค มอบหมายอาจารย์ผู้ดูแลห้องละหนึ่งคน
- จัด ย้าย หรือยกเลิกการจัดห้องให้นักศึกษา โดยรายชื่อนักศึกษาไม่ถูกลบ
- นักศึกษาหนึ่งคนอยู่ได้หนึ่งห้องต่อรายวิชาต่อช่วง ภายหลังจะเพิ่มห้องหลังกลางภาคแยกจากก่อนกลางภาค
- หน้านักศึกษาที่รับผิดชอบและจำนวนบน Dashboard ใช้ข้อมูลชุดเดียวกัน

## วิธีใช้งานในเครื่อง

เปิด Command Prompt ในโฟลเดอร์โครงการแล้วใช้ `npm start` (หรือ `npm run dev`)
ระบบเตรียมตารางใหม่อัตโนมัติผ่าน `scripts/migrate-courses.mjs` ก่อนเริ่มเว็บ
หากเปิดเซิร์ฟเวอร์ค้างไว้ก่อนอัปเดตนี้ ให้หยุดด้วย Ctrl+C แล้วเริ่มใหม่

เข้าสู่ระบบด้วย `instructor@email.kmutnb.ac.th` รหัสผ่าน `demo1234`
เปิดเมนู **รายวิชาและห้องเรียน** หรือ `/instructor/courses`
สร้างรายวิชา → เพิ่มรายชื่อ → สร้างห้องและเลือกผู้ดูแล → เลือกห้องในแถวนักศึกษาแล้วกดบันทึก
แก้ข้อมูลผิดได้ด้วยปุ่มแก้ไข ไม่จำเป็นต้องสร้างรายการใหม่

การนำเข้า Excel อ่านทุกชีตที่เป็นรายชื่อและมีหัวตาราง `ลำดับที่`, `รหัสนักศึกษา`, `ชื่อ`, `สกุล` ส่วนชีต `แบ่งกลุ่ม ...` จะไม่ถูกนำเข้าซ้ำ ระบบรองรับรวมไม่เกิน 300 คนและไฟล์ไม่เกิน 5 MB แต่ละชีตรายชื่อจะกลายเป็นแท็บล่าง เช่น `CED-2DERA` และ `TCT-1DERA` หากรหัสนักศึกษามีอยู่แล้ว ระบบจะอัปเดตชื่อ สกุล และแท็บเดิมแทนการสร้างซ้ำ สำหรับรายชื่อใหม่ ระบบสร้างอีเมลภายในจากรหัสนักศึกษาเพื่อคงความเข้ากันได้กับโครงสร้างบัญชี แต่ไม่แสดงอีเมลในตารางนี้

ไม่มีการเพิ่มนักศึกษา ห้อง หรือคะแนนสมมติอัตโนมัติ ผู้สร้างรายวิชาจะปรากฏในรายชื่ออาจารย์จากบัญชีที่เข้าสู่ระบบจริง

## สิทธิ์และข้อจำกัดของบัญชี

ในระยะพัฒนานี้ เฉพาะบัญชีอาจารย์ตัวอย่างที่มีรหัสภายใน `instructor-demo` มีสิทธิ์เริ่มสร้างรายวิชา
ผู้รับผิดชอบถูกบันทึกเป็น `courses.owner_id` จากบัญชีฝั่งเซิร์ฟเวอร์ ไม่รับจากแบบฟอร์ม
การแก้ไขรายชื่อ ห้อง และการจัดห้อง ต้องเป็นเจ้าของรายวิชาเท่านั้น
อาจารย์คนอื่นเห็นรายวิชาที่มีห้องมอบหมายให้ตน และเห็นเฉพาะรายชื่อในห้องเหล่านั้น
เชื่อมผู้ดูแลกับบัญชีอาจารย์ด้วยอีเมลที่ตรงกันและบทบาทอาจารย์ ห้ามใช้สิทธิ์นี้แทนระบบบัญชีจริงเมื่อนำไปใช้งานจริง

**การเพิ่มรายชื่อไม่ใช่การสร้างบัญชี Login** ยังไม่มีการส่งคำเชิญหรือสร้างรหัสผ่านให้อาจารย์และนักศึกษาใหม่
ก่อนทดลองหลายบัญชีจริง ต้องเพิ่มระบบจัดการบัญชีและมอบหมายผู้รับผิดชอบรายวิชาอย่างเป็นทางการ

## การเก็บข้อมูล

เก็บในฐานข้อมูล D1 จำลองบนเครื่อง ภายใต้ `.wrangler/state/v3` ของโครงการ
ปิดแล้วเปิดเว็บใหม่ข้อมูลยังอยู่ แต่ไม่ใช่การสำรองข้อมูล และข้อมูลไม่ถูกแชร์ระหว่างเครื่อง
ห้ามลบโฟลเดอร์ดังกล่าวหากต้องการเก็บข้อมูลเดิม

โครงสร้างอยู่ใน `db/schema.ts` และ migration `drizzle/0004_course_management.sql`
เครื่องมือสร้าง snapshot ใหม่แล้ว โดยแยกตารางเดิมที่มี migration 0002 และ 0003 ออกจาก 0004 เพื่อไม่สร้างซ้ำ
ตัวเตรียมฐานข้อมูลในเครื่องติดตาม migration รายวิชาแยกด้วย `course_schema_migrations` และใช้ transaction แบบ batch
ไม่เล่น migration เก่าซ้ำ ไม่ลบข้อมูลระบบเดิม ไม่เผยแพร่ขึ้นออนไลน์

## การทดสอบและตำแหน่งโค้ด

- `lib/server/course-store.ts`: validation, สิทธิ์, และคำสั่งฐานข้อมูลที่ใช้ parameter binding
- `app/api/instructor/courses/route.ts`: ตรวจ session และ origin ก่อนแก้ข้อมูล
- `features/instructor/courses`: แบบฟอร์ม ตาราง และธีมหน้าจัดรายวิชา
- `tests/course-store.test.mjs`: ฐานข้อมูล SQLite แยกชั่วคราว ทดสอบความซ้ำ สิทธิ์ การย้ายห้อง และการแยกช่วง
- ทดสอบส่วนนี้ด้วย `node --test tests/course-store.test.mjs`

## ขั้นที่ยังไม่รวม

ผลตรวจวันที่ 6 กันยายน 2569: Build, ESLint และชุดทดสอบ 17 รายการผ่าน รวมการทดสอบส่วนรายวิชา 7 รายการ
ตรวจ HTTP หน้ารายวิชาและรายชื่อนักศึกษาได้ 200; คำขอผิดปีได้ 400, ต่าง origin ได้ 403, ไม่มี session ได้ 401
ยังไม่ได้ทดสอบการกดใช้งานด้วยเบราว์เซอร์จริงทุกจุด การตรวจ TypeScript ทั้งโครงการยังไม่ผ่านเนื่องจากชนิดข้อมูล Cloudflare และ Mammoth เดิมยังไม่ครบ

ตัวเลือกถัดไปคือ (1) บันทึก Feedback การซ้อมเดี่ยวโดยไม่ให้คะแนน หรือ (2) จัดรอบสอบกลางภาคและกรรมการ
การจัดคู่ ห้องหลังกลางภาค Feedback ซ้อมคู่ รูบริกจากเอกสาร และ AI ยังไม่อยู่ในการส่งมอบขั้นนี้
หน้าประเมินเดิมบางหน้ายังเป็นโครงหน้าจอ ไม่ควรถือว่าเชื่อมระบบใหม่หรือพร้อมใช้สอบจริง
